# Instructions for coding agents

1. **Read [MASTER_DESIGN.md](MASTER_DESIGN.md) in full before planning or editing.** It is the canonical approved product-intent and roadmap source; nothing in it proves the feature is implemented.
2. Inspect current code, branches, PRs and accepted Platform contracts before acting. Do not assume that historical SHAs or experimental provider PRs are current or integrated.
3. Begin at the next unaccepted Engineer Milestone, initially **E0.M1**. Each milestone needs working behavior, negative/recovery tests, manual and typed-agent parity, an editable demonstration and exact evidence.
4. Platform owns generic Hub/local lifecycle, account/provider credentials and shared AI/review SDK. Engineer owns all exact B-Rep, solvers, parametric history, versions, assemblies, drawings and semantic CAD tools. Game Engine is a reference for proven patterns, not a source of shared CAD domain types.
5. Never bypass human-reviewed AI Apply, document revisions, stable IDs, unit/geometry validation, authorization or atomic persistence. Never claim GPU, live-model, migration or numerical acceptance based on a mock or visual approximation.
6. Propose an ADR and ask for owner approval when a technical spike reveals that a foundational decision or MVP scope must change. Preserve old documents, tested revisions, branches and user files.
7. Once implementation starts, maintain current `IMPLEMENTATION_STATUS.md`, `AI_HANDOFF.md`, milestone reports and relevant ADRs; distinguish planned work from completed and externally validated work.

For architecture and third-party sources, follow the links in the master's **Axiom family and source references** section.
