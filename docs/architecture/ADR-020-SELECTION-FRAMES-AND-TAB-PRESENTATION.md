# ADR020 — Selected-state precedence and submitted-frame feedback

Owner corrections accompanying E1.M2, software0.1.3.

The old SVG overlay projected solid boundaries with the live camera after a queued GPU frame had used an earlier matrix. This produced displaced blue contours during orbit and drew hidden edges over other bodies. Solid feedback now consists of world-space instanced line quads/point disks submitted in the model pass with the same uniform matrix/depth buffer. The integer picking attachment is write-masked for feedback; display feedback cannot change CAD identity. Selected faces retain #00AEFF and selected edges use darker #005AA3; selected state excludes coincident hover segments even when body/feature aliases differ. Source hover and CSS selected rows obey the same priority. Camera-only frames reuse unchanged world feedback buffers.

Reference overlays use the submitted frame snapshot rather than live camera state. Selected/hovered axes use the narrow long-dash/dot chain convention (line04.1), with relative24d/3d/0.5d/3d display elements and constant screen width. Reference: [ISO128-2:2022](https://www.iso.org/standard/83355.html), basic line conventions. The viewport marker is separate from the printed drawing template. They accompany an RGB XYZ origin triad consistent with the corner widget. The corner widget keeps stable focusable groups, generous transparent shaft/label targets, distinct end-on labels and pointer-down focus suppression. Keyboard activation remains available. Camera/hover/reference changes do not mutate native bytes.

A product iframe cannot set its containing tab favicon. The optional generic Platform0.1.13 presentation extension supplies a fresh per-load challenge and accepts only the active frame/source/origin and bounded public title/PNG. The CAD replies with its existing original logo rasterized locally; no credential, project metadata or geometry crosses that channel. Blocking/disconnection clears branding; recovery uses a fresh challenge. Older hosts retain their generic containing-tab icon while the CAD editor keeps its own favicon. COOP/COEP, editor lease and native authority remain unchanged. The CAD SDK remains pinned to accepted Platform0.1.12 because no SDK export changes; the optional0.1.13 shell extension is independently published before delivery. [Provider contract](https://github.com/Krozzeo/AxiomPlatform/blob/2f775b1cfff1a8fd749e6e30e2c33ca519209be1/docs/EDITOR_PRESENTATION.md).

Acceptance includes real GPU Auto hover/clicks, selected source priority, RGB origin, dashed axes, shaft clicks and axis inversion, several screenshots while selected geometry orbits, no stale solid SVG contours or GPU validation errors, native-byte equality, real hosted favicon and foreign/stale/invalid image/reconnect rejection. No CPU mock is reported as GPU acceptance.
