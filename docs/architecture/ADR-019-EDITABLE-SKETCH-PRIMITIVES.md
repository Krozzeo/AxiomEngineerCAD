# ADR019 — Editable sketch primitives in the native graph

Status: E1.M2 implemented review candidate, software0.1.3. Owner requested the next milestone after0.1.2. No owner acceptance, main merge or complete E1 claim.

## Domain and persistence

A native1 feature `sketch-primitives` uses a strict `E1.M2-sketch/1` data profile: name, support plane and up to64 stable-ID entities. Point, line, circle and axis-aligned rectangle are actual editable analytic primitives in canonical mm. Each primitive has a construction flag. Entity identity is globally unique across the graph; updating cannot change its type/identity. Rectangles retain one primitive ID; their display corners are derived, not new persistent topology. At most16 sketches, primary definition only in this measured slice; occurrence sketch editing remains future work. Coordinates fit +/-1000mm, line length exceeds1e-9mm, rectangle sides are nonzero and circle radius exceeds0.01mm with full extent within the coordinate bound. No expressions, fixed flags, solver status or claimed DOF are stored.

Support is canonical XY/XZ/YZ or the uniquely resolved top/bottom face of a supported exact primary geometry probe. A face support retains producer ID/role/kernel/state, graph dependency and same-definition binding. The existing isolated exact-kernel resolver proves the face at validation, save/version and proposal validation. The frame is derived from the proven current producer; it is not a stored pixel/raycast plane. Unsupported/absent/ambiguous references fail. A changed extrusion depth moves the supported frame after recomputation. Arbitrary planes/occurrences are explicitly unsupported.

Native0 remains readable; conversion is the existing explicit native1 conversion with original backup on Save. Native1 envelope/hash/atomic journal and immutable closure are unchanged. This adds a typed feature decoder rather than silently migrating documents. The actual0.1.2 reader rejects M2 features without rewriting source, while earlier E0/M1 files remain readable. Historical evidence binds sketch coordinates/profile and derived support frame by content hash; tampering changes validation/hash. Do not reinterpret unsupported future profiles.

## Shared commands and human editing

The six tools are `cad.sketch.inspect.v1`, `cad.sketch.create.v1`, `cad.sketch.entity.add.v1`, `cad.sketch.entity.update.v1`, `cad.sketch.entity.delete.v1` and `cad.sketch.delete.v1`. Inspect is bounded/paged ReadOnly and explicitly reports constraints unavailable. Mutations use the existing shared pure reducer, isolated before/after verification, revision/dependency CAS and receipt handling. Human MAIN changes stay unsaved until Save. Agents retain ReadOnly/LocalProposal only; full human review and atomic Apply/Save remain mandatory. Deleting a sketch refuses downstream dependencies.

The Sketch operation page opens a real plane-local editor inside the dockable Model panel. Click to place points; click twice for line, circle or rectangle. Select via geometry or primitive list; edit coordinates/radius/construction in Inspector and Update. Delete uses identity. Preview points are drafts; Escape/Cancel draft leaves stored geometry unchanged. Numeric updates and two-click commands use the inspected/captured revision, not a freshly rebased stale draft. Document-revision polling refreshes other frontends and Manager; in-progress numeric/two-click drafts retain their base and cannot rebase silently. Model fit includes source-derived sketch curves/points even without solids. Stable IDs survive Save/reload; Manager double-click opens the persisted sketch. The Model shows tessellated display curves derived from source geometry, not B-Rep solids. No new solid extrusion or drawing of arbitrary sketches is claimed. Constraints/DOF/driving dimensions are E1.M3; general extrusion is E1.M5.

## Evidence

Domain tests cover all primitives/units/frames, invalid data/degeneracy/resources/IDs, actual face resolution, immutable history/tamper detection, real old-reader refusal, agent/manual parity, full human review/Apply, stale commands and cancellation. Browser acceptance creates all four types, edits/deletes/construction, refuses invalid radii, cancels drafts, preserves history and reloads from Save. Existing numerical, native, review and vector drawing gates remain required. Physical GPU and unsupported browser evidence are reported separately. Exact-head CI plus public prepared installation are delivery gates.

## Separated Model editing

The active sketch ID, selected primitive ID, tool and construction preference participate in the existing ordered, random-channel panel view synchronization. Receivers inspect their authenticated current native sketch; no domain command or coordinate snapshot crosses the channel. The Model carries its actual primitive toolbar and its editing marker with the panel node, including native popup adoption. Embedded fallback frontends enter/exit the same sketch and synchronize selection with the parent Inspector; typed mutations still pass through the same adapter/session, CAS and isolated validation. Dirty numeric drafts retain their base when the same selection changes elsewhere. Re-selecting another entity is an explicit view-selection change. Returning to3D reuses the verified current proof and preserves frame-source safeguards. Actual Platform iframe/popup tests create a primitive in the child, edit it in the parent, verify both views/history and return without acquiring a second project lease.

Background refreshes apply only monotonic document revisions and re-check numeric/drawing draft state after awaited inspection. A late response cannot replace text entered while that response was in flight. Mutating operations temporarily disable their sketch controls until verification finishes. A delayed real inspect-response browser regression checks draft retention, alongside the existing cross-window stale-CAS refusal.
