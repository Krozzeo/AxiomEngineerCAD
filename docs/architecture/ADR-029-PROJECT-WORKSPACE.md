# ADR029 — project workspace, independent CAD documents and version branches

Status: owner-requested design/implementation, 2026-11-16. The explicit request in docs/requests/PROJECT_WORKSPACE_2026_11_16.md supersedes the former one-active-document shell. No main/stable merge is authorized.

A project is an authorized folder with a small versioned workspace index, separate native1 part/assembly files, open document sessions/tabs and an active document. A native part can contain its own modeling features and component instances. Groups are organizational component definitions, not a second mandatory part file type. New projects have no active part. Existing native documents open as legacy one-part projects without rewriting their native bytes; opting into file management creates only a project index and state directories.

The Platform project lease and identity stay stable across document activation. Each open document retains independent buffers, working history, CAD command/proposal authority, revision, proof jobs, native snapshots and recovery. Switching rejects pending fields, active source edits/commands and AI tasks; display-only viewport jobs are cancelled before switching; closing offers Save/Discard/Cancel. Requests bind the active document identity so delayed messages from a previous tab cannot modify another part with the same revision number. Editor tabs reload/rebind all context, not just viewport geometry.

Part files remain native1. Workspace catalog and version DAG use separately versioned metadata. Archived versions are immutable validated native snapshots, with explicit branch heads, parent IDs and merge receipts. Three-way merges detect overlapping edits and require explicit per-conflict choice; the resulting complete model must pass structural/exact verification. Referenced/published versions cannot be physically discarded. History operations stage recoverable metadata before native persistence and reconcile after interrupted acknowledgment. Native working revisions remain monotonic.

Cross-file instances keep stable source document/definition identity and a verified effective snapshot. Inserting uses the existing native dependency contract and rejects recursive documents/definitions. A live working source is an explicit workspace candidate, never a silent rewrite of historical published snapshots. Render/pick model keys include source identity to avoid collisions between separate documents' primary definitions. CAD mutations preserve existing scopes, human-reviewed AI Apply, exact kernels/solver pins and atomic writes.

Project browser adapts the actual MIT Game Engine browser from published experimental fc2613243f0e52623dc053de5d9bd0796e4e7024 (PR63), retaining its folder tree, breadcrumbs, inline creation, selection and drag/drop patterns. CAD thumbnails derive from actual model geometry in centered isometric projection. Platform's existing OS folder service opens authorized folders. No shell command is derived from project file contents.

Verification: tab-isolation/stale request, independent histories and close decisions, exact source-instance updates and recursion rejection, file/folder ordinary-path/hardlink/symlink denial, version immutable/recovery/merge-conflict paths, component movement/group ordering, mode visibility and active-component transparency, real Project UI and Platform installation. Complete acceptance is required before an installable completion claim. M2 mates are not silently declared complete by free-component movement.


Implementation details for 0.4.1:

- File catalog mutations prepare `.engineer-project-transaction.json` before filesystem changes. Recovery checks project/index identity and ordinary paths, then finishes the authorized operation. Delete moves files to project trash; no recursive user-file deletion occurs. Stale revisions fail before any file is created.
- Working project links use native Pinned effective snapshots with the reserved `project-working` channel. The project catalog resolves the live source by document identity, not by matching a filename. Updating a working assembly verifies a fresh source candidate before replacing only its working dependency; archives/publications retain their original closure. Offline native snapshots remain usable. This channel is distinct from published Latest/Pinned refresh behavior.
- Renderer keys are namespaced by source document, snapshot and definition. Occurrences separately retain source definition and owning document identities. This prevents producer/instance IDs reused by independent native files from affecting another document.
- External in-place editing retains the assembly tab/lease while source commands bind the independent source document. Context geometry is composed transiently with validated source snapshots; the parent working dependency is updated on Exit edit. Historical preview uses a read-only temporary document, context tokens rotate, and late requests cannot mutate the restored working document.
- Project layout, AI settings/token usage and GitHub destination are project-scoped. CAD journals, AI conversations/proposals, visibility and version DAGs are part-scoped. A GitHub pending publication remains tied to its source document.
- Move/reparent preserves rigid transforms and world placement. Repeated shared-group children must be edited in their shared context; ambiguous occurrence edits are refused. Legacy solver recipes without reliable occurrence/body mapping are not moved past their mates. The general associative mate work remains E4.M2.

Queued HTTP actions recheck document/context identity when they execute, including version and occurrence mutations. Saving a working consumer persists dirty loaded source dependencies first, then the consumer, preserving existing clean source bytes. In-place editing opens the source tab so its unsaved state remains visible.
